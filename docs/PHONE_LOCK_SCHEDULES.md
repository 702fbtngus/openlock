# Device Owner 없이 사용하는 휴대폰 잠금 스케줄

스케줄 편집에서 `What to lock` → `Entire phone`을 선택한다. 요일과 시간을 지정하고
오른쪽 위 `Save`를 누른 뒤, `Permissions & status`에서 보호가 켜져 있는지 확인한다.
PIN, 기존 모니터 서비스와 앱 위에 표시 권한을 사용한다. Device Owner, 기기 초기화,
Shizuku/ADB, 추가 전화 권한은 요구하지 않는다.

## 동작

- 스케줄이 시작될 때 휴대폰을 사용 중이면 전체 사용 PIN을 띄운다. 휴대폰을 깨우지는 않는다.
- 시스템 잠금을 먼저 해제한 뒤 OpenLock PIN을 요구한다. 시스템 PIN/지문을 대체하지 않는다.
  기존 생체 인증 옵션이 켜져 있으면 OpenLock에서도 사용할 수 있다.
- 인증은 다음 화면 꺼짐까지 유지한다. 모니터 재시작, 새 날짜의 스케줄 구간 진입,
  활성 휴대폰 스케줄 구성 변경도 재인증 사유다. 앱별/설정 보호 인증과는 별개다.
- PIN에서 뒤로가기를 눌러 인증을 건너뛰지는 않는다. 전원 버튼과 전화 앱은 사용할 수 있다.
- 스케줄 종료/비활성화/삭제 또는 보호를 명시적으로 끈 경우 전체 사용 PIN을 자동으로 닫는다.
  중복된 스케줄이 있으면 아직 유효한 휴대폰 스케줄을 계속 적용한다.
- 기존 스케줄은 `Selected apps`로 읽는다. 모드를 전환해도 이전 앱 선택을 보관하며,
  `Entire phone`에서는 보관된 목록을 앱별 잠금으로 취급하지 않는다.
  비활성 스케줄을 편집·저장해도 자동으로 활성화하지 않는다.

## 일반 설치 방식의 한계

이 기능은 앱 수준의 추가 PIN이다. PIN Activity를 벗어나면 모니터가 다시 띄우지만,
홈·최근 앱·알림창·빠른 설정을 OS 정책으로 차단하지는 않는다. 진입/복귀에는 시간 차이가
있을 수 있고 서비스 종료·권한 해제·OS의 백그라운드 실행 제한으로 보호가 약해질 수 있다.

PIN 화면에서 상태표시줄을 숨기는 것은 전체 화면 표시 기능일 뿐이다. 스와이프로 시스템
컨트롤이 다시 나타날 수 있다. 상태표시줄 차단 성공으로 표시하지 않는다.
[Android 전체 화면 표시 문서](https://developer.android.com/develop/ui/views/layout/immersive).

전화 앱과 알려진 시스템 통화 UI, SystemUI는 전체 잠금에서 제외한다. 사용자 요청으로
PIN 화면의 `Phone calls` 바로가기와 해당 버튼용 여백은 제거했다. 시스템 잠금화면의
긴급전화 기능은 기존 OS 경로를 사용한다. 전화 앱의 연락처 같은 기능도 사용 가능할 수 있다.
제조사별 수신 전화·긴급전화·알람 동작을 실기기에서 확인해야 한다. 이 예외는 사용자 전체에
몇 초간 잠금을 푸는 방식이 아니라 해당 패키지에만 적용된다.

## 구현과 검증

- Dart `LockSchedule.lockPhone`과 JSON/native map에 모드를 저장한다. 백업도 같은 직렬화를 사용한다.
- Kotlin/Dart 스케줄 평가에서 휴대폰 모드와 앱별 패키지 목록을 분리한다.
- 모니터의 300ms 휴대폰 검사, 사용자 잠금 해제 통지, 접근성 창 패키지 통지를 조합한다.
  사용 기록 조회나 Settings 노드 읽기가 늦어도 휴대폰 스케줄 평가 자체를 기다리게 하지 않는다.
- `PhoneLockState`는 활성 스케줄의 날짜/구성별 키와 메모리 내 인증을 관리한다.
  화면 꺼짐·다른 구간의 인증 콜백을 재사용하지 않는다.
- 기존 `LockActivity`에 휴대폰 모드를 추가한다. 이 모드에서는 가짜 커버 대신 실제 PIN을
  표시하고 화면 켜기/키가드 위 표시를 끈다. 종료 여부를 표시 중에도 500ms마다 재평가한다.
  실제 PIN 표시 지연이나 종료 정밀도를 300/500ms로 보장하지 않는다.
- 기존 삭제/설정 보호의 판별 규칙과 검사 작업 스레드, 앱별 인증 정책은 유지한다.

추가된 테스트는 JSON/기존 데이터 호환, 모드 변경 시 선택·활성 상태 보존, 자정 넘김/요일/
종료 경계, 중복 스케줄, 화면 꺼짐 후 재인증과 오래된 인증 거부를 검사한다.
Android JSON은 JVM 테스트용 `org.json` 구현으로 평가한다.

실기기에서 다음을 확인한다.

1. 1~2분 뒤 시작하는 `Entire phone` 스케줄을 만들고 홈/앱을 계속 보고 있어도 PIN이 뜨는지.
2. 화면 꺼짐 → 시스템 잠금 해제 → OpenLock PIN 순서와 화면을 껐을 때 다시 켜지지 않는지.
3. PIN/생체 인증 성공 뒤 앱 전환은 허용되고, 다시 화면을 끄면 재인증하는지.
4. PIN을 그대로 둔 상태에서 종료 시각이 되면 닫히는지. 자정 넘김·중복 스케줄도 확인한다.
5. 홈/최근 앱 이탈 뒤 재표시, 상태표시줄 스와이프, 수신 전화·시스템 긴급전화·알람.
   PIN에 전화 바로가기와 빈 버튼 여백이 없고 작은 화면에서도 키패드가 맞게 표시되는지.
6. 재부팅·앱 업데이트·보호 끄기/켜기, 기존 앱 잠금·설정/삭제 보호·PIN 뒤로가기.
7. 삼성 Android 17과 Xiaomi Android 16/HyperOS에서 각각 확인한다. 빌드만으로 호환성을 단정하지 않는다.

이 PC에는 Java/Kotlin/Flutter SDK가 없어 실행 검증은 GitHub Actions와 실기기에서 수행해야 한다.
